# 发布与更新

## 发布一个版本

先将仓库放到 GitHub 并配置远端。工作流文件需要先进入默认分支；当前实现不自动创建仓库、远端或 Tag。

```powershell
git pull --ff-only
git push origin main
git tag v0.1.1
git push origin v0.1.1
```

仅接受稳定版 `v主版本.次版本.修订号`（例如 `v1.2.3`）。不要复用已公开发布的 Tag；需要修正时发布新版本。Tag 的版本会覆盖源码 `VERSION` 中的本地构建默认值，无需为每次发布手动修改源码常量。

工作流使用 Windows 2022 runner 和 VS 2022：

1. 校验 Tag 格式，自动注入 `github.repository` 更新源。
2. 下载固定版本的官方依赖，核对 SHA-256 与安装器数字签名。
3. 构建原生程序并运行核心、历史与更新协议测试。
4. 生成 `GameGauge-版本-Setup.exe` 和 `SHA256SUMS.txt`。程序、设置界面、安装包 Windows 文件版本及卸载信息使用同一版本号。
5. 创建草稿 Release，上传资产并确认 GitHub 返回的 SHA-256 与本地一致，再公开发布，自动生成版本说明。

工作流仅需内置 `GITHUB_TOKEN` 的 `contents: write`。没有第三方上传 Action；checkout 固定为提交。失败时不会公开半成品 Release，同 Tag 重跑只允许恢复草稿，已发布版本拒绝覆盖。

## 软件更新

“版本与更新”提供三个手动步骤：检查更新 → 下载更新 → 安装更新。也可直接下载 Release 的安装包覆盖安装。

- 默认启动后、每六小时后台检查稳定版；默认不自动安装。
- 启用“自动下载并更新”后，自动下载，通过校验并等当前游戏退出后启动安装器。
- 安装到 Program Files 需要 Windows 管理员确认，不能绕过 UAC。取消后不会反复弹窗，可手动重试。
- 配置及游戏历史保留。未开启的游戏不能由监控器保证识别，自动安装前以当前已识别游戏的存活状态为判断。
- 更新版本按数字比较，不会降级。拒绝预发布、草稿、非预期仓库/文件名、缺少 SHA-256、超大文件和下载长度/哈希不匹配的安装包。
- GitHub API 与下载通过 HTTPS，系统证书校验保持启用，不允许重定向降级到 HTTP。安装前再次校验本地文件。
- 安装器目前没有项目自身的 Authenticode 签名。SHA-256 来源于 HTTPS GitHub Release API，它验证下载与该 Release 资产一致，不能替代独立发布者签名；官方第三方依赖另有有效数字签名。
- 更新源需要公开可读的 GitHub Release。私有仓库不支持在客户端嵌入开发者 Token；可使用公开发布仓库或手动下载。

## 本地构建

```powershell
.\build.cmd -Task Package -Version 0.1.2 -Repository owner/repo
```

`owner/repo` 必须替换为实际公开发布仓库。省略时只生成没有在线更新源的本地构建，界面会说明尚未配置，而不是伪报“已是最新”。本地脚本不会上传或发布。

## 首次线上验收

发布第一个版本后安装，再推送更高版本的 Tag；检查手动更新及自动更新、游戏运行时延期、取消 UAC 后重试、更新后版本/配置/历史。仓库尚无远端和 Release 时，这段实际跨版本升级不能在本机声称已经通过。
